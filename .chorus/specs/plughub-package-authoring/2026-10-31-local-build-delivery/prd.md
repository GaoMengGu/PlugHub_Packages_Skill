# PRD：PlugHub Skill 本地编译与目录投放

## 背景与目标

当前 Skill 已说明插件清单、DLL 构建和包验证，但把用户指定 GitHub 分支、同步 main、提交推送与 workflow 跟踪作为必需步骤。目标是让 agent 在用户目标机器完成检查 PlugHub、缺失时安装、本地开发、本地编译、验证和目录投放。

用户已确认：中英文与入口同步；本轮只改工作流；保留本机 API DLL 与 NuGet 编译引用；仅复制完整包，用户刷新；移除默认 GitHub 发布前置；未安装时从 GitHub 获取最新 PlugHub 安装。

## 需求

1. 检查：确认 agent 实际可访问的机器、操作系统、Revit 2020、PlugHub 版本及有效安装位置，定位真实被扫描的包目录和写权限。多个候选或目标机器不可访问时记录待确认项，不把开发机源码路径当作运行目录。
2. 安装：仅在 PlugHub 缺失时，从可核实的官方 GitHub 仓库获取执行时最新版本，记录来源、版本/tag 或 commit、安装方式及结果，按该版本说明安装并复查。优先使用官方提供的安装资产；若官方仅提供源码，按其构建安装说明处理。无可用版本、不兼容或缺少权限时报告阻塞，不静默更换版本或猜安装命令。
3. 开发与编译：按用户插件需求创建或修改完整包，保留现有项目和 build.ps1 入口，支持 -RevitApiDir 与 -UseRevitApiNuGet 两种本地编译引用路径。不得依赖上传代码到 GitHub Actions 才能交付。
4. 验证与投放：本地构建成功、清单及载荷验证通过后，复制清单、DLL、图标和必需依赖，保持相对目录。目的地必须来自安装配置、官方说明或用户明确路径；复制前处理冲突与文件占用，保护其他包和配置，复制后核对目标文件并重新验证。
5. 刷新与报告：默认只复制，不调用刷新、安装 UI 或重启 Revit。说明用户刷新步骤，分别记录静态验证、构建、复制结果与未执行的 Revit runtime smoke test，不宣称仅经静态检查的包已运行成功。
6. 文档与检查一致：更新两套 Skill 及其参考文件、相关 README 和 agent 入口；发现元数据仅在涉及旧流程或入口描述时同步。更新仓库静态校验器，不再强制旧 GitHub 工作流，继续校验清单契约、图标、发现入口及文件规范。

## 边界

本轮交付是 Skill 指令和配套校验修改，不创建样例或业务插件，不执行用户机器上的安装/编译/投放。未来 agent 执行插件任务时才按该流程操作。保留用户已有未提交改动，Git 操作仅在明确需要版本控制交付时按授权执行。仓库自身 Gitee 同步 workflow 不属于插件开发默认流程，保留其职责。

## 验收

双语流程顺序与行为一致；无 GitHub 分支或访问远程构建的条件下可进入本地任务；已安装/未安装、来源或目录不明、无写权限、构建失败、验证失败和目标冲突都有明确处理；静态校验本身能拒绝缺少关键本地流程规则的文档。通过检查不等于本次已经完成 Windows/Revit 端到端验证。
