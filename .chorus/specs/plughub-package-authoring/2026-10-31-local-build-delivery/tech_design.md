## 工作流约定

安装和目录事实需要在编写最终安装说明前核查 PlugHub 官方 GitHub README、发布资产和相应源码契约；证据附加到 Chorus References。当前仓库并未提供可证明目标机器安装状态的资料，本方案不虚构固定安装命令或固定版本。实现者需确认官方仓库身份后写明可追踪入口，后续 Skill 执行时重新查询最新版本，核实操作系统和 Revit 兼容性。

默认顺序为检查环境与已有改动 → 确认/安装 PlugHub 并复查 → 定位包工程 → 按需求实现 → 本地构建 → 包验证 → 复制 → 复制后核查 → 报告用户刷新步骤。无法访问目标机器时，可报告本地静态工作成果，但不得声称安装或投放完成；前置受阻项明确记录。

安装检测至少结合实际安装文件、注册/配置或官方安装产物依据，不以名为 PlugHub 的源码文件夹判定成功。发现已安装版本时不自动升级。来源、兼容性或目的地不明时停止相关写操作并请求澄清；headless 环境通过已有平台评论或问题面板提出，避免终端交互阻塞。

本地编译沿用项目实际支持的 .NET SDK/构建脚本参数，不假定所有宿主可直接运行 Windows PowerShell 或 Revit。NuGet 是本地编译引用来源，不能把 Revit API 运行时 DLL 随意当作插件依赖分发。不得弱化现有 net48、PlugHub.Contracts、稳定 ID、完整 commandType 和真实图标规则。

投放使用已验证包的完整相对结构。先核实目的目录、已有目标文件和写权限，更新已有同名包前保存可恢复副本；存在不明内容、占用或不完整复制时保留原文件并报告失败，不清理整个包根目录。复制后的文件列表或哈希与源包对应，并对目标包运行现有验证器。不新增自动刷新、强制解锁或重启步骤。

## 验证方案

1. 构建并运行仓库静态校验器，运行两份随 Skill 分发的包验证器构建检查，确认已有清单和图标约束仍生效。
2. 用临时仓库副本进行轻量回归自检：原始新文档通过；分别去掉两种语言中的安装检查、GitHub 最新版安装、本地编译或目录投放关键要求时应失败。临时数据不写入真实安装目录，不新增业务样例插件。
3. 审阅双语决策表：已安装、缺失需安装、目标机器不可访问、多目录、无权限、构建/验证失败、包冲突、投放成功但等待刷新；确认每种状态的下一步及报告用词明确。
4. 全仓检查旧前置表述并审阅命中语境，避免把允许下载 GitHub 安装文件和仓库 Gitee 同步误删。执行 git diff --check，保留既有无关改动。

本轮可证明文档完整性、静态校验与回归拒绝能力；不声称已证明真实 Windows/Revit 安装、刷新或插件命令运行。若环境缺工具，记录具体未执行项和失败输出。

## 场景审阅证据与边界

以下为双语决策表和复制步骤的指令审阅，不是目标机执行记录：

| 场景 | 指令要求的结果 |
| --- | --- |
| 已安装 | 从有效 addin、DLL、版本和配置确认后复用，不自动升级。 |
| 未安装 | 重新查询官方最新版，按该 tag 说明安装，复查后才记成功。 |
| 目标不可访问/非 Windows | 停止安装投放，允许单独报告可完成的静态工作。 |
| 来源不明/不兼容/无发布 | 停止安装并澄清，不换来源或旧版。 |
| 多目录 | 列候选及 addin/配置证据，确认正在使用的实例。 |
| 无权限/UAC 无法完成 | 保留文件，通过平台请用户/IT 处理，不绕过权限。 |
| 构建或包验证失败 | 停止投放，报告失败输出，修复后重建重验。 |
| 同名包/id 冲突/不明文件 | 确认归属，备份到扫描范围外；不明内容先澄清。 |
| 占用/复制中断/目标验证失败 | 不强制解锁，只撤回本次变更并恢复原包；恢复失败保留证据，不报告完成。 |
| 复制完成 | 全相对文件列表及 SHA-256 核对、目标重验后报告已复制待用户刷新；Revit runtime 仍独立待测。 |

本轮只交付指令、校验器及回归自检，不安装 PlugHub、不创建样例/业务插件、不投放包、不操作 Revit。尚未验证真实 Windows/UAC/目标目录复制、用户刷新或 Revit 命令运行。
